# PR Scanner

Use this procedure to scan all open pull requests across configured repositories, run the Steward review gate on each, and post review comments with findings.

## Prerequisites

- `gh` CLI installed and authenticated (`gh auth login`)
- `git` installed
- Python 3.10+
- Access to the target repositories via the authenticated `gh` account

## Safety boundary

- The scanner posts review comments on PRs but does not modify PR state (no labels, merges, closes, or approvals).
- PR checkouts are isolated in a temporary work directory and cleaned up between scans.
- Use `--dry-run` to verify behavior before posting real comments.
- The scanner uses `gh` CLI for all GitHub API access — no tokens are stored in config files.

## Procedure

### One-shot scan (explicit repos)

Scan specific repositories by passing them as arguments:

```sh
python3 scripts/steward_scan_prs.py \
  --repos owner/repo1 owner/repo2 \
  --dry-run
```

Flags:
- `--repos REPOS [REPOS ...]` — Repositories to scan (`owner/repo` format)
- `--config CONFIG` — Path to a steward review configuration file
- `--config-dir CONFIG_DIR` — Directory containing per-repository review configs
- `--work-dir WORK_DIR` — Working directory for PR checkouts (default: temp dir)
- `--output OUTPUT` — Path to write the summary report (default: `~/.config/steward-os/pr-scan-summary.json`)
- `--dry-run` — Run the review but don't post comments to GitHub

### Config-driven scan (fleet-wide)

For fleet-wide scanning, create a configuration file:

```json
{
  "repositories": [
    "owner/repository1",
    "owner/repository2"
  ],
  "scan": {
    "post_comments": true,
    "work_dir": "/tmp/steward-pr-scan",
    "output": "~/.config/steward-os/pr-scan-summary.json"
  }
}
```

Then run:

```sh
python3 scripts/steward_scan_prs_config.py \
  --config setup/pr-scan-repos.json \
  --dry-run
```

Flags:
- `--config CONFIG` — **Required.** Path to the repositories configuration file
- `--review-config CONFIG` — Path to a steward review configuration file
- `--review-config-dir CONFIG_DIR` — Directory containing per-repository review configs
- `--dry-run` — Run the review but don't post comments to GitHub

### GitHub Action (automatic)

The included `.github/workflows/pr-scan.yml` runs hourly and on manual dispatch. It reads `setup/pr-scan-repos.json` by default, or accepts a comma-separated repo list on manual trigger.

## Review comment format

Each PR receives a comment like:

```markdown
## 🤖 Steward PR Review

**Repository:** owner/repository
**Branch:** `feature-branch`
**Head SHA:** `abc12345`
**Base:** `main`
**Lane:** deep
**Status:** ready

### 🔍 Quality Commands
- ✅ **test**: passed
- ❌ **lint**: failed
  ```
  error: unused import
  ```

---
*Generated by Steward PR Scanner*
```

## Summary report

The scanner writes a JSON summary to `~/.config/steward-os/pr-scan-summary.json` (or the path you configure):

```json
{
  "total_prs": 5,
  "by_status": {"ready": 3, "blocked": 2},
  "by_repo": {
    "owner/repo1": {"total": 2, "by_status": {"ready": 1, "blocked": 1}}
  },
  "prs": [...]
}
```

## Workflow

1. **List PRs** — The scanner uses `gh pr list` to find all open PRs on configured repositories.
2. **Checkout each PR** — For each PR, the scanner clones the repository and checks out the PR branch into an isolated work directory.
3. **Run steward review** — The scanner runs `steward_review.py` on each PR checkout, producing a manifest with status, lane, and command results.
4. **Post review comment** — The scanner formats the manifest into a structured review comment and posts it on the PR using `gh pr comment`.
5. **Write summary** — The scanner writes a JSON summary report of all scanned PRs.

## Staleness and escalation

- The scanner operates on the current state of each PR at scan time. If a PR is updated after scanning, run the scanner again.
- If a PR's review status is `blocked`, the scanner reports it but does not take action. Remediation requires a new scan after fixes are committed.
- Missing deterministic evidence or a blocked manifest is reported in the review comment.

## Example usage

### Scan a single repository (dry run)

```sh
python3 scripts/steward_scan_prs.py \
  --repos keithah/steward-os \
  --dry-run
```

### Scan multiple repositories

```sh
python3 scripts/steward_scan_prs.py \
  --repos keithah/steward-os keithah/unifi-mcp \
  --output /tmp/scan-summary.json
```

### Fleet-wide scan with config

```sh
python3 scripts/steward_scan_prs_config.py \
  --config setup/pr-scan-repos.json
```

### Use custom review configuration

```sh
python3 scripts/steward_scan_prs.py \
  --repos keithah/steward-os \
  --config /path/to/review-config.json
```
