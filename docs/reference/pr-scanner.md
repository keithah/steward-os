# Steward PR Scanner

Scan all open pull requests across configured repositories, run the Steward review gate on each, and post review comments with findings.

## Overview

The PR scanner extends Steward from a single-repo, local-only review tool into a fleet-wide PR review system. It:

1. Lists all open PRs on configured repositories via the `gh` CLI
2. Clones each PR into an isolated work directory
3. Runs the existing `steward_review.py` manifest/lane engine against the PR checkout
4. Posts a structured review comment on each PR with status, lane, evidence gaps, and command results
5. Writes a JSON summary report of all scanned PRs

## Quick start

### One-shot scan (explicit repos)

```sh
python3 scripts/steward_scan_prs.py \
  --repos keithah/steward-os keithah/unifi-mcp \
  --dry-run
```

### Config-driven scan

```sh
# Copy and edit the example config
cp setup/pr-scan-repos.example.json setup/pr-scan-repos.json
# Edit setup/pr-scan-repos.json to list your repos

python3 scripts/steward_scan_prs_config.py \
  --config setup/pr-scan-repos.json
```

### GitHub Action (automatic)

The included `.github/workflows/pr-scan.yml` runs hourly and on manual dispatch. It reads `setup/pr-scan-repos.json` by default, or accepts a comma-separated repo list on manual trigger.

## CLI reference

### `steward_scan_prs.py`

| Flag | Description |
|------|-------------|
| `--repos REPOS [REPOS ...]` | Repositories to scan (`owner/repo` format) |
| `--config CONFIG` | Path to a steward review configuration file |
| `--config-dir CONFIG_DIR` | Directory containing per-repository review configs |
| `--work-dir WORK_DIR` | Working directory for PR checkouts (default: temp dir) |
| `--output OUTPUT` | Path to write the summary report |
| `--dry-run` | Run the review but don't post comments to GitHub |

### `steward_scan_prs_config.py`

| Flag | Description |
|------|-------------|
| `--config CONFIG` | **Required.** Path to the repositories configuration file |
| `--review-config CONFIG` | Path to a steward review configuration file |
| `--review-config-dir CONFIG_DIR` | Directory containing per-repository review configs |
| `--dry-run` | Run the review but don't post comments to GitHub |

## Repos config format

```json
{
  "repositories": [
    "owner/repository"
  ],
  "scan": {
    "post_comments": true,
    "work_dir": "/tmp/steward-pr-scan",
    "output": "~/.config/steward-os/pr-scan-summary.json"
  }
}
```

## Review comment format

Each PR receives a comment like:

```
## 🤖 Steward PR Review

**Repository:** owner/repository
**Branch:** `feature-branch`
**Head SHA:** `abc12345`
**Base:** `main`
**Lane:** deep
**Status:** ready

### 🔍 Quality Commands
- ✅ **test**: passed
- ❌ **lint**: failed
  ```
  error: unused import
  ```

---
*Generated by Steward PR Scanner*
```

## Summary report

The scanner writes a JSON summary to `~/.config/steward-os/pr-scan-summary.json` (or the path you configure):

```json
{
  "total_prs": 5,
  "by_status": {"ready": 3, "blocked": 2},
  "by_repo": {
    "keithah/steward-os": {"total": 2, "by_status": {"ready": 1, "blocked": 1}}
  },
  "prs": [...]
}
```

## Prerequisites

- `gh` CLI installed and authenticated (`gh auth login`)
- `git` installed
- Python 3.10+
- The target repositories must be accessible via the authenticated `gh` account

## Security

- The scanner uses `gh` CLI for all GitHub API access — no tokens are stored in config files
- PR checkouts are isolated in a temporary work directory, cleaned up between scans
- Review comments are posted via `gh pr comment` — the scanner never modifies PR state (labels, merge, close)
- The `--dry-run` flag lets you verify behavior before posting real comments
